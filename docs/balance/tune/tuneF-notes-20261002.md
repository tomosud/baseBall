# 守備のしやすさ・ファウル・打球の向き — 所見 2026-10-02

## なぜ

タイミング方式（`tuneT-notes-20261002.md`）を実機で遊んだ所見:
「打ちやすいが HR は出にくい。打たれると走者を打ち取るのが難しく、点がどんどん入ってつまらない」
「人の手では球を拾うのが難しい。拾ったら指の下に隠れて見えない」「打つこと自体にもっと幅がほしい。芯を外したらファウル、芯の表示、どこに当たったか」。

## 変更（app.js / styles.css / cpu.js）

1. **拾いやすさ**（`isPlayingBallPickable`）
   - 拾える距離 36 → 56px（`fielderPickupRadius`）。
   - 打球は止まるまで拾えなかったが、130px/s 以下（`fielderPickupRollSpeed`）なら転がっていても拾える。深い打球は従来どおり止まってから待つ。拾える球は止まった球と同じ赤。
   - 拾った瞬間、球は指の位置へ 90ms で吸い付く（瞬間移動して指の下に消えていた）。持っている間は指より大きい黄色の輪（`.batting-ball.is-held::after`）。
   - CPU（cpu.js）も同じ拾える条件を使う（`T.isBallPickable`）。
2. **芯の表示**: バットの背景に芯の帯（根もとから 49〜71% = 「芯!!」が出る範囲）。当たった位置が光る（芯なら金、外れなら白）。
3. **ファウル**（`checkPlayingFoul` / `callPlayingFoul`）
   - 当たった位置から、本塁〜1塁・3塁の線と同じ角度で広がる扇の外へ、塁の高さに届く前に出たらファウル。後ろへ飛んだ打球もファウル。
     最初は本塁を起点にしたが、バットは左右に動かせるので、真上に打った球でも本塁から 40〜60px 横で当たると即ファウルになった。起点を当たった位置に変えた。
   - バットの描画の端から 12px 以上外で当たったらその場でファウル（`foulTipOvershoot`）。当たり判定の半径はバットの外まで届くため。
   - ファウルはストライク（2 ストライク後は増えない）。走者とカウントは打つ前に戻る。テストログに `foul`（理由つき）、集計は打席・インプレーから外す。
4. **打球の向きをタイミングで振る**: ずれ 50ms ごとに 25°（早い = 左、遅い = 右。バットが真横を過ぎてから当たると球は左上へ返るのと同じ向き）。
   **それまで打球はタイミングに関係なくほぼ真上（-4〜+1°）に飛んでいた**。左右の打ち分けがなく、ファウルも投球のカーブを引き継いだ横流れだけで起きていた。

## 読み

1. 拾いやすさの効果が最も大きい（上級同士 27 → 4 点）。ボットは球の真上を正確に押せるので、これは主に「転がっている球を拾える」効果。人の場合は範囲の拡大と輪の表示も効くはず。
2. 130px/s では中級同士が目標帯（得点 4、アウト率 63%、HR 6%）。上級同士は 13 点とまだ多いが、上級ボットの精度は仮置き（校正前に合わせ込まない）。
3. ファウルで「タイミングが合わない打球は前に飛ばない」が入り、ファウル率が腕前の段階になった（5% / 30% / 54%）。
4. 2 ストライク後のファウルは三振にならないので、中級以上の三振はほぼ 0% のまま。空振りが起きるのは初級だけ。

## 次
