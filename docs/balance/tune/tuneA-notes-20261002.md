## 読み

1. **中級同士だけなら 0.33 で目標帯に入る。** 合計得点 5、アウト率 53%、HR 13%。打球速度も 452〜885 と分布を持つ。
2. **上級同士は 0.25 まで下げないと試合が終わらず、0.18 まで下げると初めて目標帯に近づく**（得点 4、アウト率 48%、1点差以内 88%）。
3. **同じ値では両立しない。** 中級に合う 0.33 では上級が 980 に張り付いたまま（p10 で 733）、上級に合う 0.18 では中級が 0-0 続きになる。
   原因は `launchSpeed` が **スワイプ速度に比例** していること: `120 + impulse × 芯度 × (0.55+0.55×スクエア度)`, `impulse = バット速度 × scale`。速く振れる人（上級）は芯度が高いぶんさらに速くなり、scale を下げても「上級は上限・中級は弱い」の差が残る。
4. **一本の倍率（scale）は引き手として不十分。** 上級の打球が 980 に届かず、かつ中級の打球が 400〜700 に残る形が要る。

## 次の候補（調整 A の第2案）

`batHitPowerScale` の一律倍率ではなく、**スワイプ速度の寄与を圧縮して芯度の寄与を残す**形:

```
impulse_eff = IMPULSE_REF × tanh(impulse / IMPULSE_REF)      // 速く振っても頭打ち
launchSpeed = 120 + impulse_eff × 芯度 × (0.55 + 0.55 × スクエア度) + …
```

- `IMPULSE_REF` を 500〜700 で振る。impulse 1000（上級の典型）で tanh が 0.76〜0.96 → 上級の芯の当たりで 700〜900、芯外しで 400〜600。中級（impulse 500〜700）は 350〜600。
- 「速く振るほど強い」は残る（単調増加）が、無限に速く振っても得をしない。
- 上限 980 と `homeRunClearRatio` 0.18 はそのままで、HR が「芯度 0.8 以上 **かつ** 上壁に勢いを残して届く」の 2 門番に戻るはず。

この変更は `physics` の数値ではなく `reflectBallFromBatModel` の式の変更（仕組みの変更）なので、計画書 §4.1 のとおり Opus 側の判断で行い、感度分析は同じ手順で回す。
`IMPULSE_REF` を `physics` に置けば以後は数値の引き手として扱える。

0.25 以下では「送球なし」が 0% に近づき、守備が毎打球で投げている。アウト率 70〜80% は README の実測（6/6, 5/6）と整合する。
