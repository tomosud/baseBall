# 打球の強さをタイミングで決める（batPowerModel: "timing"）— 所見 2026-10-02

## なぜ

実機で遊んだ所見（2026-10-02）: 「ホームランが出やすすぎ」「走者を打ち取るのが難しすぎ」。速度や当たりにくさの数値ではなく、根本の解決が要る。

旧方式では打球の強さがスワイプの速さにほぼ比例していた。接触の窓（±80ms、半径 35px）が広くほとんど空振りしないので、
腕前の差は「速く振れるか」だけに出て、速く振れる人は毎回 HR 圏（打球速度 850 以上）に届いた（`tuneA2-notes-20261002.md`）。

**方針: 当たる（接触の窓は広いまま）けど、上手く合わせないと飛ばない。**

## 仕組み（app.js）

- **タイミングのずれ** `getSwingTimingError`: 「バットが真横（角度 0）になる瞬間」と「球がバットの高さ（batY）に届く瞬間」の差（秒）。正 = 振り遅れ、負 = 振り早い。
  接触の判定（半径）とは独立に測るので、当たったかどうかと「合っていたか」を分けられる。
- **タイミング係数** `getTimingFactor`: |ずれ| ≤ `batTimingPerfect`（10ms）で 1、そこから `batTimingFalloff`（45ms）かけて `batTimingFloor`（0.3）まで直線で下がる。
- **打球の勢い** = `batHitPowerMax`（780）× 振りの足り具合（圧縮前 impulse / `batFullSwingImpulse` 500、上限 1）× タイミング係数。
  打球速度の式（芯度・スクエア度・投球速度の項）はそのまま。普通に振れば振りの速さは満タンなので、速く振っても得はない。
- **ホームラン**には従来の条件（上壁での余力・当たりの質 0.8）に加えて、タイミング係数 1（満点の範囲）が要る。
- 打球の方向（反射と振りの向き）は旧方式のまま（圧縮後の impulse を使う）。
- 旧方式は `batPowerModel: "swing"` で戻せる。

### 表示

- 空振り: バットの上に「早い！」（振り終わっても球が来ていない）「遅い！」（通り過ぎてから振った・判定のあとに振った）「← ずれ」「ずれ →」（通過時にバットの左右の外）。
- 当たり: 満点の範囲なら「ジャスト！」、係数 0.65 以上なら「少し早い／少し遅い」、それ未満は「早い！／遅い！」。数字は出さない。

### ボットの振り始め（機構の定数）

打者ボットの振り始めリードを 0.16 → 0.10 秒に変更。0.16 は「接触率が最大」になる値で、タイミング方式ではずれの中央値が -59ms（早振り）だった。
0.10 でずれの中央値が 0 付近（中級 -3ms、上級 -7ms）。ずれの幅（p10〜p90）は 上級 ±38ms / 中級 ±55ms / 初級 ±100ms で、腕前（`timingSigma`）がそのまま段階になる。
`run-baseline.js` の既定、`record.js`、ひとりで遊ぶときの CPU（`startCpuIfSolo`）を 0.10 に揃えた。

## 読み

1. **上級同士の試合が初めて全部終わる。** 打球速度が腕前（タイミングの精度）に応じて段階的に分かれ、旧方式のような「上限への張り付き」がなくなった。
2. 中級同士は目標帯付近（得点 3、アウト率 65%、HR 7%）。得点はやや少なめ。
3. 上級同士はまだ得点が多い（27）。HR 17% に加えて、**HR でない速い打球（750 以上）で守備が追いつかない**（送球なし 60%）。
   これは打撃側ではなく守備側の問題（拾えるのが止まってから、動く走者に当てるしかない）で、根本案 B（フライ捕球）・C（ゴロ捕球）の領分。
4. HR の当たりの質を 0.88 に上げても HR は 17% → 15% とほとんど変わらない。満点のタイミングで捉える上級ボットは芯度も高いため。
5. 上級ボットの精度（`timingSigma` 25ms など）は仮置き。人の上級がどのくらいの精度かは実プレイの記録で校正する。
