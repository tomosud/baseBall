対象: `baseline-20261002-0057.md`（3回制、9カード × 16試合）と打者の感度スイープ（`tools/balance/sensitivity-batter.js`）。
物理パラメータは現在値のまま。**数値はボットの腕前設定（仮置き）に依存する**ので、絶対値ではなく構造を読む。

## 結論（3行）

1. **打球が出ると守備にできることがほぼ無い。** 中級以上の打球は 9 割が速度上限（980px/s）で上壁まで届き、拾えるようになる前に走者が一塁に着く。上級の打球に対する守備のアウト率は 0〜3%、送球すらしない打球が 96〜99%。
2. **上級同士の試合は終わらない。** 三振 0%・四球 1%・インプレー 99%・HR 率 75% で、アウトが取れないため 3 回制でも仮想 25 分の上限に達する（16 試合中 0 完了）。
3. **打撃の難しさは「タイミング」ではなく「横位置」にある。** タイミング誤差 σ=90ms でも接触率 100%。HR 率を決めるのは横位置の誤差で、σ=5px で 70〜90%、15px で 40%、30px で 10〜30%。

## 2. なぜそうなるか（機構の読み）

### 2a. 打球速度が上限に張り付く
`reflectBallFromBatModel` の `launchSpeed = clamp(120 + impulse × 芯度 × (0.55+0.55×スクエア度) + …, 150, 980)`。
`impulse = バット速度 × 0.55` で、スワイプ 1500px/s 程度から上限 980 に届く。スマホのフリックは 1500〜3000px/s が普通なので、**芯でなくても上限**になる（中級の打球速度 p10 が 622）。
打球は上壁へ届き、「深い打球」として `deepHitPickupDelay` 0.7 秒が乗る。上級走者（秒11回連打）は 2.8 秒で一塁に着くので、拾えた時点で刺せる走者がいない。

### 2b. 接触の許容が広い
スイング 0.065 秒 + 猶予 0.085 秒、バット長 59px、判定半径 35px。ゾーン手前の球速は 200〜300px/s なので、**±80ms** ずれても当たる。誤差ゼロの打者で振り始めのリードを 0.04〜0.20 秒まで動かしても接触率 100%・質 0.86〜0.89 だった（`calibrate.js`）。
結果、三振が出ない。

### 2c. HR の門番は横位置だけ
`homeRunHitQuality` 0.8 と `homeRunClearRatio` 0.18 のうち、後者は速度上限の打球では常に満たす（残り飛距離 890px ≫ 127px）。実質 **芯度 ≥ 0.8** だけで、芯度は当たり位置（`hitRatio` 0.6 からのズレ × 1.4）で決まる。横 10px のズレで芯度 0.76 → HR にならない。
つまり HR は「横位置を ±8px で合わせられるか」のゲームになっている。README の意図（「芯!!」が出る当たりだけ）とは一致するが、タイミング側の技術がほぼ要らない。

### 2d. 初級のデッドボール
指をゾーン中央近く（σ40px）に置く初級打者には、投球の 31% が当たる。デッドボールで 1 点なので得点源になっている。README の未決事項「スイング中のデッドボール」と同根。

## 3. ボット由来の可能性があるもの（次に確かめること）

- **打者の予測が正確すぎる**: ボットは投球の軌道を式で先読みする。人は球速の読み違えで横位置を外す。横位置 σ を腕前で 7/15/30px にしているが、この値の根拠はまだ無い。→ 実プレイの記録で校正（計画書 Phase 6）。
- **常に全力スワイプ**: 速く振る理由しかない（速いほど速度上限に届きやすく、弱く打つ利点が無い）ので人も全力になるはずだが、要確認。
- **守備が「刺せない」と判断すると投げない**: 人はダメ元で投げる。走者が止まって避けようとした瞬間に当たる偶然が起きうる。アウト率を数%押し上げる可能性はあるが、構造は変わらない。
- **走者の連打間隔**: 上級 11回/秒は README 実測の上限付近。中級 6回/秒でも守備のアウト率は 34%。

## 4. 引き手の候補（計画書 §6 に進むなら）

効きの方向だけ。値は感度分析で決める。

| 症状 | 候補 | 備考 |
| --- | --- | --- |
| 打球が全部上限速度 | `batHitPowerScale` 0.55 を下げる / 上限 980 を下げる / impulse のスワイプ速度依存を圧縮（tanh） | 「速く振るほど強い」は残しつつ、芯外しで速度が落ちる幅を作る |
| 三振が出ない | `battingSwingLingerDuration` 0.085 / `batContactRadius` 35 を縮める | 接触窓 ±80ms → ±40ms くらいが目安。README の「振り遅れの緩和」との兼ね合い |
| HR 多すぎ | `homeRunHitQuality` 0.8 → 0.9 / 速度上限を下げて `homeRunClearRatio` を効かせる | 門番を 1 つ（芯度）から 2 つ（芯度 × 強さ）に戻す |
| 守備が間に合わない | `deepHitPickupDelay` 0.7 を縮める / `runnerBoostMax` を下げる | README は「拾いにくくする方向は行き止まり」としている。打球速度を下げれば深い打球自体が減るので、まず 2a から |
| 初級のデッドボール | スイング中はデッドボール無効（README 未決） / `deadBallRadius` 20.8 を縮める | 仕組みの判断を先に |

**順番の提案**: 2a（打球速度の飽和）→ 2b（接触窓）→ 2c（HR 門番）。2a を直すと深い打球が減って守備が成立し、2c の `homeRunClearRatio` も意味を取り戻すので、1 本で複数の症状に効く。
