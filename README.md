# や球

1台の端末を使って、青軍と赤軍で対戦する野球ゲームです。画面の上半分がピッチャー、下半分がバッターのエリアになり、投球、打撃、送球をタッチ操作で行います。

スマートフォンやタブレットの横持ちを想定しています。PCでもマウス操作で遊べます。

## 遊び方

1. `index.html`を開きます。
2. タイトル画面で試合形式を選びます。
   - `9回で対戦`: 9回制
   - `3回で対戦`: 3回制
3. `PLAY BALL!`の表示が消えたら試合開始です。

## 起動方法

Windowsでは、リポジトリ内の`run_static.bat`を実行するとブラウザが開きます。

```bat
run_static.bat
```

ポートを変えたい場合は、番号を指定できます。

```bat
run_static.bat 9000
```

Pythonが使える環境なら、次のコマンドでも起動できます。

```sh
python -m http.server 8765 --bind 127.0.0.1
```

そのあとブラウザで `http://localhost:8765/index.html` を開いてください。

## 画面の見方

- 上側: ピッチャー側の操作エリア（`PITCHER`と表示、中央の二重円がマウンド）
- 下側: バッター側の操作エリア（`BATTER`と表示）
- 中央付近: 投球と打撃のプレイエリア
- `B / S / O`: ボール、ストライク、アウトのカウント
- `🐶青軍` / `🐱赤軍`: 各チームの得点（青軍が犬、赤軍が猫）
- `1回表`など: 現在のイニング

表は青軍の攻撃、裏は赤軍の攻撃です。

## 操作

### ピッチャー

ピッチャー側のエリアの奥（2塁寄り）にマウンドの円があります。投球はこの円の中に指を置いてから始めます。円の外を触っても投球は始まりません。守備の流れの中でピッチャー側を触ったときに、意図せず投球が始まってしまうのを防ぐためです。

円の中でボールを置き、相手側へスワイプして投げます。

スワイプの速さで球速が変わります。指の軌道を曲げると、投球にも曲がりがつきます。

**ボールを掴んでいて投げられる間、マウンドの円が赤くなります。** 指の下にボールが隠れて見えないので、これが「今持っている」目印です。指を離す（投げる）と元の色に戻ります。

スワイプ自体はマウンドの円やピッチャー側のエリアを越えて振り抜いて構いません。制限があるのは投げ始めの位置だけです。円の中から投げ始めた球は、指を離す位置がエリアの外でも球速と伸びを保ちます。円を出ても、持っている間は赤いままです。

投げた球がピッチャー側のエリアを出られずに止まった場合は`投げミス`と表示され、**ノーカウントでやり直し**になります。ボールにもストライクにもならないので、指が滑ったときは投げ直してください。

### バッター

バッター側のエリアをタッチするとバットを構えます。ボールに合わせて、投手方向へ素早くスワイプするとスイングします。

タイミングとバットの当たり方で打球の強さや方向が変わります。強い打球は青く表示されます。

ホームランになるのは、芯で捉えた強い当たりが、外野の壁まで勢いを残したまま届いたときだけです。「芯!!」が出るくらいの当たりでないと、壁に届いても跳ね返って外野の打球になります。必要な勢いは盤面の大きさに対する割合で決まるので、画面の大きさが変わっても出やすさは変わりません。

バッター側に指を置いている間、指の位置に肌色の薄い輪が出ます。これがデッドボールの判定です。投球がこの輪に当たると、輪が砕けて`デッドボール`と表示され、**投げた側（ピッチャーのチーム）に1点**入ります。ボールにもストライクにもならないので、カウントは動きません。

指はバットの位置とは別に動かせます。ボールの通り道から指を外しておけば当たりません。

### ランナー

打球が出るとランナーが走り出しますが、**何もしないとほとんど進みません**（13px/秒）。画面下部（波線より下）を連打した分だけ走ります。波線より上はすべて守備側の領域なので、連打はこの範囲の中で行ってください。加速量は下半分に出るゲージで確認できます。

速さは**連打の間隔**で決まります。押す間隔が短いほど速くなり、上限は167px/秒です。

| 連打 | 本塁→一塁 |
| --- | --- |
| なし | 25.0秒 |
| 秒3回 | 6.7秒 |
| 秒6回 | 3.9秒 |
| 秒12回 | 2.8秒 |

連打をやめると速度は**0.27秒で半分**まで落ちます。これは損ではなく武器です。守備は「この速さで走り続ける」と読んで先を狙って投げてくるので、送球の直前に手を止めると読みが外れて当たりません。全力で走ったあと急に止まると、0.4秒で23px、0.6秒で46pxのズレが生まれます（当たり判定は半径17px）。

逆に、止まったままのランナーは先読みが要らないので簡単に当てられます。止まって避けるのは一瞬だけにして、抜けたらまた連打してください。

連打は、守備側がボールを拾って送球を構えている最中でも効きます。アウトが出た瞬間には、残ったランナーに自動で加速がかかります。

ランナーは走る人の姿で表示されます。足の運びは実際に走った距離に連動しているので、連打で加速するほど速く走って見えます。ランナーが複数いるときは色で見分けます。

ホームランが出たあとはランナーを狙えないので、`走者に当てろ！`の表示と的の点滅は消えます。

### 守備

打球が出るとランナーが走り、守備モードになります。守備モードの間はエリアの色分けが下へ広がり、**画面の上4分の3が守備側**、下4分の1がランナーの連打エリアになります。投球に戻ると色分けも半分ずつに戻ります。

**アウトを取るには、拾ったボールをランナー本人にぶつけます。塁に送球しても何も起こりません。**

打球は今までどおり、止まって赤くなるまで拾えません（外野まで飛んだ打球はさらに待ち時間があります）。ボール付近をタッチして拾い、赤く点滅しているランナーへ向けて弾いてください。

**一度投げたあとのボールは、飛んでいる最中でも転がっている最中でも、いつでも拾い直して投げ直せます。** 外したらすぐ拾い直して次を狙えます。ボールを拾ったあとに引っ張れる距離の制限は変わりません。

- ランナーは走っている間だけ狙えます。塁に着いてセーフになったランナーには当たりません。
- フォアボールで進塁中のランナーも対象外です。
- 送球が壁に当たると、跳ね返らずにその場へ落ちます。壁に触れた球ではアウトを取れないので、拾い直して投げ直してください。
- アウトを1つ取った送球もそこで死にます。続けて刺すには拾い直して投げ直す必要があります。

ランナーの足元に出る赤い輪が当たり判定の目安です。輪はランナーの絵より小さいので、体をかすめただけでは当たりません。輪の中を通すつもりで投げてください。

ランナーは走り続けるので、今いる場所ではなく**進んだ先を狙って**投げる必要があります。連打で加速したランナーほど大きく先を読まないと当たりません。

塁は薄い波線で位置だけを示しています。送球の的ではありません。

## 基本ルール

- 3ストライクで三振アウトです。
- 4ボールでフォアボールです。
- 3アウトでチェンジです。
- ヒットすると打者と塁上のランナーが自動で進塁します。
- ランナーがホームに到達すると得点です。
- 得点が入ると`+1`のメッセージがそのチームの得点表示へ飛んでいき、着いたところで数字が弾みます。デッドボールの得点も同じ演出です。
- チェンジのたびに`CHANGE!`と一緒に**野球の豆知識が1行**出ます。ピッチャー側とバッター側の両方に、向かい合わせで同じ文が表示されます。
- 豆知識は`CHANGE!`が消えたあとも盤面に残ります。**ピッチャーがボールを掴んだ時点で消える**ので、読み終わるまで待てます。出るときも消えるときも0.7秒かけてゆっくり溶けます。
- 最終回終了時に得点が多いチームの勝ちです。
- 最終回裏で後攻の赤軍が勝ち越した場合は、その時点で試合終了です。
- 同点の場合は引き分けです。延長戦はありません。

## リセット

試合中に左上の`リセット`を3秒長押しすると、3回制または9回制を選んで最初からやり直せます。

試合終了後は`もう一度`で同じ試合形式を最初から遊べます。

## セーブ

試合中の状態はブラウザに自動保存されます。ページを再読み込みしても、途中から再開できます。

新しく試合を始めたとき、リセットしたとき、試合が終了したときは保存データが消えます。

## 音について

投球、打撃、アウト、得点、ホームランなどに効果音があります。

音は最初のタッチやクリックの時点で有効になります。ブラウザの仕様で、それより前には鳴りません。

再生には Web Audio を使っているため、`<audio>`要素は作られません。そのため端末に「メディア再生中」として表示されることはなく、同時に鳴らせる音の数にも制限がありません。

# 開発メモ（続きをやる人へ）

ここから下は遊び方ではなく、**なぜ今こうなっているか**と**次に触るならどこか**の記録です。

タイトルは**「や球」**です（`index.html` の `<title>` と `.game-title`）。プロトタイプ扱いをやめた時点で付けた名前なので、`Baseball Prototype` という表記が残っていたら直してください。

## このゲームが目指しているもの

野球のルールからは意図的に外れています。判断の軸は次の4つです。

1. **操作の巧拙が勝敗に直結すること。** 運ではなく、指の精度と読みで差がつくこと。
2. **画面を複雑にしないこと。** 情報を足すのではなく、既にある要素の意味を変えて深くする。
3. **1台の端末で2人が同時に触れること。** ピッチャーとバッターは別々の指で同時に操作する（マルチタッチ前提）。
4. **発展の余地を残すこと。** 個別の数値ではなく仕組みを変える方向で調整する。

## 経緯（なぜこうなったか）

改修は「野球のルールを守る」方向ではなく「操作が効く」方向に進んできました。時系列で見ると一本の筋になっています。

### 1. 投球の許容範囲を広げた
マウンドの円**から投げ始めれば**、指がエリアの外へ抜けても球速と伸びを保つようにしました（`pitchReleaseGraceMs` / `pitchReleaseGraceRatio`）。制限は投げ始めの位置だけです。スワイプを振り抜けないと気持ちよくないためです。

あわせて、エリアを出られずに止まった投球は**ノーカウントの`投げミス`**にしました。指が滑った事故で不利になるのを避けるためです。

### 2. アウトの取り方を「塁」から「走者」に変えた
**これが最大の転換点です。** 元は塁に送球すればアウトでしたが、
- 塁は動かないので、狙いは覚えゲーになる
- 走者側にできることが「連打」しかない

という詰まりがありました。ランナー本人に当てる方式にすると、守備は**動く的の進んだ先を読む**必要が生まれ、走者は**進み方を変える**ことで抵抗できます。両側に技術が生まれます。

塁は薄い波線になり、位置を示すだけの表示になりました。

### 3. 守備を弱めて走者を残す方向へ
走者が取られすぎたので、拾いにくくする以外の手で緩めました。
- 壁に当たった送球は跳ね返らずその場に落ち、その球ではアウトを取れない
- 1アウト取った送球もそこで死ぬ（続けて刺すには拾い直す）
- 走者へ投げる球だけ0.6倍に減速（`fielderThrowSpeedFactor`）。投球は1倍のまま
- アウトが出た瞬間、残った走者に自動でブーストが乗る（`runnerBoostOnOutRatio`）

代わりに、**投げたあとはいつでも拾い直して投げ直せる**ようにしました。外しても取り返せるので、守備側の手数は減っていません。

### 4. デッドボールを足して、バッターの指に意味を持たせた
バッター側の指の位置に判定の輪を出し、当たるとピッチャー側に1点。バットの位置とは別に指を動かせるので、**ボールの通り道から指をどけておく**という新しい操作が生まれました。ピッチャー側から見ると、バッターの指を狙うという攻め手が増えます。

### 5. 走者の速度を「連打の量」から「連打の間隔」へ
最後の大きな変更です。旧モデルは**しきい値**でした。1タップ +17px/s に対し減衰が -46px/s²（一定）なので、`46 ÷ 17 = 2.7回/秒` を超えると上限に張り付きます。実測でも秒4回でほぼ頭打ち（秒5回3.00秒 / 秒10回2.68秒）で、速く叩いても報われませんでした。

減衰を**速度に比例**（指数減衰）に変えると、釣り合う速度が `1タップ量 × 連打回数 ÷ 減衰率` になり、連打間隔がそのまま速度になります。そのうえで基本速度を大きく下げました。

これで「**止まる**」が操作として意味を持ちます。守備は等速を前提に先を読むので、送球の直前に手を止めると読みが外れます。逆に止まりっぱなしは先読みが要らず簡単に当てられるので、止まるのは一瞬だけ、という駆け引きになります。

### 6. 見た目と当たり判定を分離
走者は8コマの走りスプライトになりました（頭が上・足が下に描かれているので、進行方向へ `rotate(進行角 - 90°)` で回します）。当たり判定は絵とは別で、絵より小さい赤い輪が判定の目安です。**絵は大きく、判定は小さく**という分離は、見やすさと難度を別々に調整できるので今後も維持する価値があります。

### 7. 分かりにくさを消した
- **上壁沿いの左右コーナーに、拾えるまで1.2秒かかるゾーン**がありましたが廃止しました（通常の深い打球と同じ0.7秒になります）。破線の囲いが画面にあるのに何のゾーンか読み取れず、方針1（複雑にしない）に反していました。
- ピッチャーがマウンドでボールを持っているとき、**指の下にボールが隠れて掴んでいるか分からない**問題がありました。持っている間だけマウンドの円を赤くして解決しています。状態を文字で説明せず、既にある図形の色で示す形です。

### 8. 待ち時間に読むものを置いた
チェンジの間は誰も操作できない空白の時間でした。ここに**野球の豆知識を1行**出しています。1台を2人で挟んで持つので、ピッチャー側は180度回して向かい合わせにしてあります。

読む時間の作り方として、最初はチェンジの表示時間そのものを 1800ms → 3200ms に延ばしましたが、**待たせるのをやめて「消えるきっかけ」を操作に紐付ける**形に変えました。`CHANGE!` が消えても豆知識は盤面に残り、**ピッチャーがボールを掴んだ瞬間に消えます**。ゆっくり読みたい人は待てて、急ぎたい人は投げれば進むので、どちらも足止めされません。テンポを固定の秒数で決めない、というのは他の待ち時間にも使える考え方です。

出入りは 700ms の opacity トランジション（ディゾルブ）です。`display` を切り替えると補間できないので、`is-hidden` ではなく `is-visible` の付け外しで動かし、`visibility` だけ消え切ってから落としています。溶けて出るぶん読み始めが遅れるので、`CHANGE!` の表示は 1800ms → 2700ms（1.5倍）にしてあります。

文面は **`trivia.js` の `BASEBALL_TRIVIA` だけ**にあります。1行足すだけで増えるので `app.js` を触る必要はありません。全部が1行に収まることを 390/420/900px 幅で確認しています（全角25文字くらいが上限）。2回続けて同じものは出ません。

### 9. 文字まわりの整理
`PITCHER` / `BATTER` のラベルにチーム名と絵文字が入っていて、すぐ横の得点表示と**同じ情報が二重に出ていました**。ラベルは役割だけにし、誰の側かは文字色で示す形に変えました（チーム名は画面に1回ずつ）。

あわせて、その場しのぎで入っていた非対称な指定を消しています。赤軍のラベルだけ 1.08rem / 太さ800、得点の名前だけ 1.3rem という指定があり、色以外は上下で同じであるべき場所が食い違っていました。今は両側同じ値です。区切り線からの距離も上下14pxでそろえてあります。

画面下のヒントは英語の長文（`Pitcher: swipe up to pitch / Batter: swing up`）で、`white-space: nowrap` のため**画面幅を超えて切れていました**。短い日本語にし、`left`/`right`＋`text-align: center` で折り返せる形にしています。3サイズ（390 / 420 / 900px）で、盤面の文字要素が画面外へはみ出していないことを機械的に確認しました。

### 10. 処理の重さ
ヒッチの原因を順に潰しました。最終的に**効いたのは`<audio>`要素の廃止**です（1205ms のフレームスパイクが 18〜26ms に）。途中で「環境の問題」と誤って結論づけましたが、Web Audio 化で完全に消えたので、原因は要素の破棄処理でした。ほかに、毎フレームの `getBoundingClientRect` をキャッシュ（世代番号で無効化）、IndexedDB の接続再利用と書き込みの250msデバウンス、`height`/`top` ではなく `transform: scaleY()` でのエリア分割、などを入れてあります。

## 現在の主要パラメータ

すべて `app.js` の `physics` オブジェクト（`const physics = {` 付近）にあります。

### 走者

| 名前 | 値 | 意味 |
| --- | --- | --- |
| `runnerBaseSpeed` | 13 | 連打なしの速度（px/s）。走るための速度ではなく「止まって避ける」ための速度 |
| `runnerBoostPerTap` | 43 | 1タップの加速量（px/s） |
| `runnerBoostMax` | 154 | ブースト上限。合計の最高速は 13+154=167px/s |
| `runnerBoostDecayRate` | 2.6 | 減衰**率**（1/s）。速度ではなく時定数。半減0.27秒 |
| `runnerBoostOnOutRatio` | 0.2 | アウト時に残る走者へ与えるブースト（上限比）。絶対値で約31px/s |
| `runnerBoostAreaTopRatio` | 0.75 | 守備モード中の画面分割。これより下だけが連打エリア |
| `walkAdvanceSpeed` | 124 | フォアボール自動進塁（タップ無効なので別枠） |

釣り合う速度は `runnerBoostPerTap × 連打回数/秒 ÷ runnerBoostDecayRate`。**`runnerBaseSpeed` / `runnerBoostPerTap` / `runnerBoostMax` を同じ倍率で掛ければ、全速度がその倍率になり、連打の手応えと避け性能の形は変わりません。** 減衰率は時定数なので、ここを触ると手応えごと変わります。

### 守備・当たり判定

| 名前 | 値 | 意味 |
| --- | --- | --- |
| `PLAYING_RUNNER_HIT_RADIUS` | 17 | 走者に当てる判定の半径（px）。`physics` ではなく定数 |
| `.runner-target-ring` | 31px | 判定を示す輪（`styles.css`）。走者より下のレイヤ |
| `fielderThrowSpeedFactor` | 0.6 | 走者へ投げる球の速度倍率。投球は対象外 |
| `deepHitPickupDelay` | 0.7 | 深い打球が拾えるようになるまでの追加待ち（秒） |

### 打撃・投球

| 名前 | 値 | 意味 |
| --- | --- | --- |
| `battingSwingThreshold` | 330 | スイングと判定するスワイプ速度 |
| `batContactRadius` | 35 | バットの当たり判定半径 |
| `battingSwingLingerDuration` | 0.085 | スイング後も当たり続ける猶予（秒） |
| `homeRunClearRatio` | 0.18 | ホームランに必要な壁越えの余力（盤面比） |
| `homeRunHitQuality` | 0.8 | ホームランに必要な芯の捉え具合 |
| `deadBallRadius` | 20.8 | デッドボール判定の半径 |
| `moundCenterRadius` / `moundRadius` | 18 / 46 | 投げ始めを認める円 |
| `pitchReleaseGraceMs` / `Ratio` | 140 / 0.82 | エリア外で指を離したときの猶予 |

ホームランの必要勢いは**盤面の大きさに対する割合**で決めています。画面サイズが変わっても出やすさが変わらないようにするためなので、絶対px に戻さないでください。

### 豆知識のテキスト

`trivia.js`（`index.html` が `app.js` より先に読み込む素の`<script>`）。配列に文字列を足すだけで増えます。表示側は `showBaseballTrivia` / `hideBaseballTrivia` / `pickBaseballTrivia`（`app.js`）で、消えるきっかけは `updatePlayingMoundHold` が握っています。ディゾルブの長さは `styles.css` の `.overlay-trivia` の `transition`（700ms）で、`.is-visible` 側と非表示側の両方を同じ値にしておく必要があります。

### 走者スプライト

`assets/sprite/runner-run.png`（704×128、8コマ横一列、アルファのみ）。CSS の `mask-image` で抜き、色は `background` が決めます。この作りのおかげで、色分け（`.color-0/1/2`）と的の赤点滅（`.is-target`）が両方そのまま効きます。コマ送りは `RUNNER_STRIDE_PIXELS`（40px 進むごとに1周）で走った距離に連動しています。

元のシートは4×2で、罫線はグレー・人物は黒だったので輝度＋アルファのしきい値で連結成分として8体を抽出しました。並び順は元のままだと足を畳んだコマが偏るので、**隣り合うコマのピクセル差の合計が最小になる巡回順**を総当たりで求めて `1→3→2→6→4→8→7→5` に組み替えてあります。

## 調整のやり方

**この数値はすべて実測で決めています。** 変えたら測ってください。感覚で決めた数字は入っていません。

計測は Playwright で実際にブラウザを動かして行います。ローカルサーバは

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

テストは `page.evaluate` の中からゲームの内部関数（`spawnRunnerOnHit`、`launchPlayingBall`、`finishPlayingPitch`、`getPlayingBasePositions` など）を直接叩き、`requestAnimationFrame` を回して結果を読みます。よく測ってきた項目は次のとおりです。

- **走者の速度曲線**: 連打を秒0/2/3/4/5/6/8/10/12回で合成し、本塁→一塁（420×860で385px）の到達時間を測る
- **避け性能**: 全力で走らせてから連打を止め、「等速だと思った位置」との差が判定半径17pxを超えるまでの時間を測る
- **当たり判定の実寸**: 走者を固定して送球を横にずらし、当たる最大ずれを二分探索する
- **守備の成立性**: 打球6パターン（浅いフライ／左右のライナー／両ラインのゴロ／深いセンター）で、拾えるまでの時間＋送球時間と、走者の到達時間を比べる
- **ホームラン率**: 画面サイズを変えて複数回打たせ、出現率が盤面比で一定か確認する
- **フレーム時間**: アイドル／投球中／守備中（走者3人）／守備中＋連打の4状況で中央値・p95・最大を取る

見た目の変更は、スクリーンショットを撮って**差分の実寸を測って**確認します（グロウの広がりを目測で判断して一度間違えたことがあります）。

## 未決・次に触るなら

**未決のまま残っていること**

- **スイング中のデッドボール**: バッターがボールの線上に指を置いてスイングすると必ずデッドボールになります（指が同じx座標で必ず成立、90pxずらせば不成立、と実測済み）。「スイング中はデッドボールにしない」案を出しましたが、判断は保留のままです。

**バランスの引き手（効きが分かっているもの）**

- **走者が全然セーフにならない場合**: `runnerBoostMax` だけを上げる（154→190 など）。基本の遅さと避け性能はそのままで上限だけ伸びます。全体を速くしたいなら基本・1タップ・上限を同じ倍率で。
- **アウトが取れなさすぎる場合**: `PLAYING_RUNNER_HIT_RADIUS` を戻す（17→20 など）。輪（`styles.css` の `.runner-target-ring`）も同じ比率で合わせてください。判定と輪の見た目がずれると理不尽になります。
- **守備が強すぎる場合**: `fielderThrowSpeedFactor` を下げる、`deepHitPickupDelay` を伸ばす。

現在の力関係は実測で、打球6パターンに対し秒6回連打で6中6が守備勝ち、秒12回で6中5が守備勝ちです（一塁到達の競争として測った場合）。走者側にやや厳しい配分になっています。

**やらない方がいいこと**

- 打球を拾いにくくする方向での難度調整（すでに何度も行き止まりになっています）
- ホームランの条件を絶対pxに戻すこと
- 画面に情報を足すこと
